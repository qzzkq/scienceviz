## 1. Суть

Программа на C++ моделирует, как за 13 миллиардов лет почти однородное вещество Вселенной стягивается гравитацией в паутину из волокон, узлов и пустот. Вещество описывается как газ с давлением на трёхмерной сетке: плотность перетекает между соседними ячейками. Расчёт идёт минимум на трёх машинах, обмен между ними мы пишем сами. Результат показывается видео, которое рендерит отдельный модуль.

## 2. Как это связано с космосом

На самых больших масштабах Вселенная устроена как пена: галактики собраны в нити и стенки, в местах пересечения сидят скопления, между ними — огромные пустоты. Это видно на картах реального неба.

Ранняя Вселенная была почти идеально однородной: реликтовое излучение показывает неровности плотности в тысячные доли процента. Вопрос космологии — как из почти ровного получилась пена.

Ответ — гравитация плюс расширение. Где вещества чуть больше, оно притягивает соседнее и уплотняется дальше; расширение пространства этот процесс тормозит. Аналитически это считается, только пока неровности малы. Дальше уравнения нелинейные, и результат можно получить только численно.

Наш код делает это в миниатюре:

| В коде | Что это в природе |
|---|---|
| Периодический куб | кусок Вселенной в несколько сотен мегапарсек; «дальше то же самое» |
| Плотность в ячейке | среднее количество вещества в этом объёме |
| Начальное состояние | почти ровное поле с малыми случайными неровностями, статистика из наблюдений |
| Расчёт | 13 с лишним миллиардов лет эволюции |
| Результат | поле плотности сегодня, в котором должна проявиться паутина |

## 3. Цели

**Цель разработки.** Создать распределённую программу, которая воспроизводит образование крупномасштабной структуры Вселенной, и показать, что она даёт ту же картину, что научные симуляции, и ускоряется при добавлении узлов.

**Цели изучения:**

1. **Инженерная, главная.** Научиться раскладывать большую физическую задачу на несколько машин: как резать пространство, что пересылать, как синхронизировать, где теряется время.
2. **Физическая, обосновывающая.** Понять, как гравитационная неустойчивость в расширяющейся Вселенной строит паутину, и уметь проверить расчёт по известным решениям.

**Чего проект не делает.** Новой науки о Вселенной мы не получим: такие расчёты делают с 1980-х годов, современные идут на сетках в тысячи раз больше. Новое здесь — собственный распределённый код и измерения его масштабирования.

## 5. Физическая модель

**Что моделируем.** Периодический куб со стороной 200–500 Мпк/h.

**Координаты.** Сопутствующие: сетка растягивается вместе с пространством, куб в расчёте не растёт. Расширение задаётся масштабным фактором a(t): a = 1 сегодня, a ≈ 0,02 на старте (красное смещение около 50).

**Уравнения** (ρ — сопутствующая плотность, v — скорость относительно сетки, φ — потенциал):

```
расширение:   (da/dt)/a = H0 · sqrt(Ωm / a³ + ΩΛ)
масса:        ∂ρ/∂t + (1/a) ∇·(ρ v) = 0
импульс:      ∂(ρv)/∂t + (1/a) ∇·(ρ v v + P) = −H ρ v − (1/a) ρ ∇φ
гравитация:   ∇²φ = (4πG / a) · (ρ − ρ_средняя)
давление:     P = c² ρ            (изотермический вариант)
              P = (γ−1) ρ e       (адиабатический, плюс уравнение энергии)
```

Точный вид множителей при a в члене с давлением зависит от выбора переменных. Его надо зафиксировать в документе с уравнениями до начала кода.

**Параметры космологии.** Стандартные значения ΛCDM (Ωm около 0,3, ΩΛ около 0,7, h около 0,7), задаются в конфиге.

**Оговорка про физику.** Настоящая тёмная материя — не газ: её частицы пролетают друг сквозь друга, а газ с давлением так не умеет. На масштабе волокон и пустот картина та же, внутри скоплений распределение другое. В литературе газ повторяет тёмную материю на больших масштабах с точностью около 1% по спектру мощности, но эта цифра получена для газа, движущегося в поле тёмной материи. Что чисто газовая Вселенная даст ту же паутину — наш вывод, он проверяется сравнением с эталонными кубами.

## 6. Начальные условия

1. Генерируется случайное гауссово поле неровностей плотности. Его статистика задаётся спектром мощности ΛCDM — готовой формулой (подгонка Эйзенштейна–Ху).
2. Неровности малы: проценты от средней плотности.
3. Скорости задаются согласованно с плотностью по линейной теории, иначе структура начнёт расти с задержкой.
4. Зерно генератора фиксируется в конфиге, чтобы запуски на одном и на трёх узлах начинались с одного и того же поля.

Для изотермического газа есть ещё параметр — скорость звука. Она задаёт масштаб, мельче которого давление не даёт веществу сжиматься. Разумно подобрать её так, чтобы этот масштаб был около 1–2 ячеек.

## 7. Численный метод

### Что хранится в ячейке

- плотность ρ;
- импульс ρ·v по трём осям;
- энергия — только в адиабатическом варианте;
- гравитационный потенциал φ.

### Что такое поток

Вещество не появляется и не исчезает, оно только переходит из ячейки в соседнюю через общую грань. **Поток** — сколько чего-то проходит через грань за единицу времени. Для массы это плотность, умноженная на скорость: F = ρ·v.

Весь расчёт газа — одна формула (в 1D для наглядности):

```
ρ_новая = ρ_старая − (dt / dx) · (F_правая − F_левая)
```

Новое содержимое ячейки равно старому, минус вытекшее через правую грань, плюс втекшее через левую. В 3D граней шесть, формула та же.

Следствия:

- **Масса сохраняется точно.** Что одна ячейка отдала, соседняя ровно столько же получила.
- **Ячейке нужны только соседи.** Поэтому расчёт газа легко режется на узлы.

Для импульса формула та же, но поток другой: импульс переносится движением (ρ·v·v) и передаётся давлением P. Давление расталкивает вещество, когда оно слишком сжалось, — этим газ отличается от «пыли».

### Как считается поток на грани

Грань лежит между двумя ячейками с разными значениями. Формула, которая смешивает левое и правое значение с учётом скорости звука, называется решателем Римана. Варианты — в развилке 3.

### Ограничение на шаг по времени

За шаг ничто не должно пролететь дальше одной ячейки (условие Куранта):

```
dt ≤ C · dx / (|v| + c_звука),   C около 0,3–0,5
```

Шаг общий для всего куба, выбирается по самой быстрой ячейке.

### Гравитация

Гравитация меняет скорость вещества:

```
импульс += −ρ · (наклон φ) · dt
```

Наклон φ — разность потенциала в соседних ячейках, это локально. Сам потенциал находится из уравнения Пуассона, и он зависит от вещества во всём кубе, а не только от соседей. Отсюда главная развилка по распределёнке (развилка 4).

### Расширение

a(t) считается заранее из уравнения Фридмана и хранится таблицей. В уравнениях он даёт множители при потоках и гравитации и «хаббловское трение»: скорости относительно сетки постепенно затухают.

### Один шаг программы

1. Узлы обмениваются слоями гало.
2. Решается Пуассон, получается φ.
3. Находится общий dt по условию Куранта.
4. На каждой грани считается поток.
5. Плотность и импульс обновляются по формуле потоков.
6. К импульсу добавляются гравитация и хаббловское трение.
7. Время и a(t) сдвигаются; раз в N шагов пишется снимок.

Шаги 4–6 каждый узел делает сам, сеть нужна в шагах 1–3.

### Защита от сбоев

Плотность не должна уходить в ноль или минус: нижний порог и проверка на каждом шаге.

## 8. Распределённые вычисления

**Разрезание.** Куб режется на слои по одной оси, по слою на узел. На трёх узлах — три слоя, у каждого два соседа; из-за периодичности первый и последний тоже соседи.

**Гало.** У каждого слоя с двух сторон по 1–2 слоя чужих ячеек — копии границы соседа. Перед расчётом потоков узлы обновляют эти копии.

**Что пересылается за шаг:**

| Когда | Что | Кому |
|---|---|---|
| Перед расчётом потоков | граничные слои плотности и импульса | двум соседям |
| На каждой итерации Пуассона | граничный слой потенциала | двум соседям |
| При выборе шага | одно число: максимальная скорость | всем |
| При проверке сходимости | одно число: невязка | всем |

**Проверка правильности.** Запуск на трёх процессах должен давать тот же результат, что на одном. Для газа — с точностью до бита. Для итерационного решателя возможны расхождения в последних знаках из-за порядка суммирования, поэтому сравниваем с допуском.

**Что измеряем:**

- время шага по фазам: потоки, гравитация, обмен, запись;
- сильное масштабирование: сетка фиксирована, процессов 1, 2, 3 и больше;
- слабое масштабирование: на каждый процесс одинаковый кусок, куб растёт вместе с числом процессов;
- влияние сети: три процесса на одной машине против трёх машин.

Три узла дают три точки на графике, поэтому масштабирование меряем по числу MPI-процессов, а три машины — демонстрация межузлового обмена.

**Ожидание по литературе.** У кода Cholla на 74 000 GPU обмен гало занимает примерно десятую часть шага, эффективность слабого масштабирования 82%. Газовая часть будет масштабироваться хорошо, узким местом станет гравитация.

### Соединение машин

Отдельная и важная часть работы: куратор прямо называет целью «понять, как связать компьютеры в сеть и какие при этом возникают проблемы синхронизации». Это не настройка «по пути», а результат, который показывается в отчёте.

**Что нужно, чтобы три машины считали одну задачу:**

| Что | Как | Зачем |
|---|---|---|
| Сеть | проводной гигабитный коммутатор; Wi-Fi только для первой пробы | обмен гало идёт каждый шаг, задержки сети прямо входят во время расчёта |
| Адреса | фиксированные IP или имена в `/etc/hosts` на каждой машине | MPI должен находить узлы по имени |
| Вход без пароля | SSH-ключи между всеми машинами | `mpirun` сам запускает процессы на других узлах |
| Одинаковое окружение | одна версия MPI и библиотек, одинаковые пути к программе | разные версии MPI между собой не работают |
| Доставка программы | общая папка по NFS или копирование сборки на каждый узел | на всех узлах должен быть один и тот же исполняемый файл |
| Сетевой экран | открыть порты MPI между машинами | иначе процессы не соединяются |
| Список узлов | файл с именами машин и числом процессов на каждой | `mpirun --hostfile` раскладывает процессы |
| Привязка к видеокарте | каждому процессу своя GPU | после перехода на GPU |
| Перезапуск | контрольные точки на диск | если узел отвалился, расчёт продолжается с последней точки |

**Порядок настройки:**

1. Две машины, программа «привет от каждого процесса» через `mpirun`.
2. Три машины, тест «пинг-понг»: замер задержки и пропускной способности сети.
3. Прототип обмена гало на простом уравнении диффузии: результат совпадает с одной машиной.
4. Настоящий расчёт.

**Что измеряем про сеть:**

- задержку одного сообщения и скорость передачи больших блоков;
- долю времени шага, которая уходит на обмен, при разных размерах сетки;
- разницу между проводом, Wi-Fi и процессами на одной машине;
- что происходит, когда одна машина медленнее других.

**Проблемы, которые ожидаем встретить:**

- **Разная мощность машин.** Шаг общий, поэтому все ждут самую медленную. Лечится слоями разной толщины.
- **Порядок обмена.** Если два соседа одновременно ждут друг от друга, расчёт зависает. Поэтому отправка и приём делаются одним вызовом `MPI_Sendrecv`.
- **Разный результат на разном железе.** Разные процессоры и компиляторы могут давать расхождения в последних знаках; сравниваем с допуском.
- **Обрыв узла.** MPI по умолчанию роняет весь расчёт; спасают контрольные точки.

На кластере НГУ большую часть настройки делает сам кластер (очередь задач, общая файловая система, быстрая сеть). Поэтому собрать три своих машины руками стоит в любом случае: именно там видно, как всё устроено.

## 10. Визуализация

- **Метод.** Для каждого пикселя луч идёт сквозь куб и накапливает свечение и поглощение по пути. Значение между ячейками — интерполяция по восьми соседним.
- **Цвет.** Логарифм плотности переводится в цвет и прозрачность: пустоты тёмные, волокна светятся, узлы яркие.
- **Камера.** Летит по сплайну, заданному в конфиге. Между снимками расчёта кадры интерполируются, чтобы рост структуры был плавным.
- **Выход.** Кадры PNG, сборка в видео через ffmpeg.
- **Разрешение.** Для сетки 512³ честное разрешение — Full HD; 4K имеет смысл с 1024³.
- **Старт без симуляции.** Рендер отлаживается на готовых кубах CAMELS и Quijote или на синтетических данных.

## 13. Развилки

### Развилка 1. Как описывать вещество — решено: газ с давлением на сетке

| Вариант | Что хранится | Что говорит литература | Вывод |
|---|---|---|---|
| Газ без давления («пыль») | плотность, скорость | после пересечения потоков описание «становится бесполезным»; решение уходит в дельта-пики и вакуум | только как первый шаг отладки |
| Модель слипания (вязкость) | плотность, скорость | скелет паутины воспроизводит «чрезвычайно хорошо», но структура более нитевидная и менее комковатая, чем в N-body | запасной вариант |
| **Газ с давлением** | плотность, импульс, энергия | стандартный метод (Enzo, RAMSES, Cholla); на больших масштабах повторяет тёмную материю | **основа** |
| Жидкость с тензором разброса скоростей | ещё 6 компонент | есть теория, готовой численной схемы для 3D нет | не брать |
| Прямое уравнение Власова (6D) | функция распределения | 64³ × 64³ требует 256 ГБ | не брать |
| Шрёдингер–Пуассон | волновая функция | нужна сетка мельче длины волны, шаг по времени падает как квадрат ячейки | не брать |
| Частицы + сетка (PM) | частицы и плотность | верная физика тёмной материи; стандартный метод | второй семестр, гибрид с газом |
| Старый N-body (Барнс–Хат) | частицы | не периодический, без расширения; распределённое дерево сложнее PM | не развивать |

**Почему газ с давлением.** Совпадает с тем, что просил куратор; шаг ячейки зависит только от соседей; нет пересылки частиц между узлами; нагрузка на узлы всегда одинаковая; легко переносится на GPU; уравнения корректны при любых плотностях.

**Что теряем.** Внутри скоплений физика тёмной материи воспроизводится неточно.

**Сравнение с PM, если вопрос поднимется снова:**

| | Газ на сетке | PM |
|---|---|---|
| Соответствие словам куратора | прямое | через «N-body тоже можно» |
| Физика тёмной материи | приближённая | верная |
| Сложность обмена между узлами | ниже | выше (частицы мигрируют) |
| Сложность схемы на одном узле | выше | ниже |
| Число шагов | тысячи | сотни |
| С чем сверять | Enzo, Cholla, блин Зельдовича | FastPM, спектр мощности |

### Развилка 2. Какой газ — открыто

| Вариант | Полей | Плюсы | Минусы |
|---|---|---|---|
| Изотермический (P = c²ρ) | 4 | нет уравнения энергии; на порядок проще; для паутины достаточен | ударные волны не греют газ, узлы плотнее, чем должны быть |
| Адиабатический (с энергией) | 5 | полная физика «неохлаждаемого газа» | в холодных сверхзвуковых потоках сеточные коды дают ложный нагрев; нужна «двойная энергия» |

**Рекомендация.** Начать с изотермического, адиабатический добавлять, когда заработают три узла.

**Как выбрать.** Посмотреть в 1D-прототипе на блине Зельдовича, насколько отличаются профили плотности.

### Развилка 3. Схема потоков — предварительно: первый порядок с HLL

Два независимых выбора.

**Как смешивать левое и правое значения:**

| Вариант | Когда годится |
|---|---|
| Брать с той стороны, откуда течёт | только газ без давления |
| HLL | простой рецепт в несколько строк; начать с него |
| HLLC | точнее, лучше держит резкие границы |

**Точность по пространству:**

| Схема | Слоёв гало | Картинка | Сложность |
|---|---|---|---|
| Первый порядок | 1 | волокна размыты | день работы |
| Второй порядок (MUSCL с ограничителем наклона) | 2 | резкие волокна | неделя |
| PPM, как в Enzo | 3 | лучшая | избыточно |

**Рекомендация.** Писать первый порядок с HLL, толщину гало сделать параметром. Второй порядок — первое улучшение после работающего 3D.

### Развилка 4. Гравитация на нескольких узлах — открыто

Главное место проекта по распределёнке: потоки газа локальны, гравитация глобальна.

**Как работают варианты:**

- **БПФ.** Плотность раскладывается на волны разной длины, каждая делится на квадрат своего волнового числа, результат собирается обратно. Ответ точный, за один проход. Преобразование трогает весь куб, поэтому узлы пересылают друг другу большие куски данных.
- **Итерации.** Потенциал в ячейке подгоняется под среднее шести соседей с поправкой на плотность, много раз подряд. За итерацию информация уходит на одну ячейку. Ускорения: тёплый старт (начинать с потенциала предыдущего шага) и многосеточный метод (решать ту же задачу ещё и на сетках грубее в 2, 4, 8 раз).
- **Двухуровневый.** Ближнюю часть силы узел считает сам локальным БПФ, дальнюю — общим расчётом на сетке в 4 раза грубее.

| Вариант | Обмен за шаг | Плюсы | Минусы |
|---|---|---|---|
| Свой распределённый БПФ поверх обычного FFTW | один глобальный «все всем» | точное решение; на периодической равномерной сетке самый быстрый; кода немного | второй механизм обмена в коде; хуже масштабируется |
| Итерации: сопряжённые градиенты с тёплым стартом | много обменов гало | тот же механизм, что у газа; простой код | сходится медленнее многосеточного |
| Итерации: многосеточный метод | много обменов гало | лучше масштабируется; ложится на GPU | сложнее отладка; решение приближённое |
| Двухуровневый (как в PMFAST) | локальный БПФ плюс малый глобальный | глобальный обмен меньше в 64 раза; терпит медленную сеть | нужно сшивать ближнюю и дальнюю силы |
| Готовый FFTW-MPI | скрыт в библиотеке | работает сразу | обесценивает работу; только как эталон |

**Факт из литературы.** В работе 2026 года многосеточный решатель с тёплым стартом сравнялся с распределённым БПФ на нескольких GPU и дал до двух раз меньше времени.

**Рекомендация.** Итерации с гало: весь код держится на одном механизме, и это картинка куратора «кубик считает соседние».

**Порядок работы при этом выборе:**

1. Один узел — БПФ через FFTW, чтобы отладить физику.
2. Три узла — сопряжённые градиенты с тёплым стартом, потом многосеточный метод.
3. БПФ остаётся эталоном правильности.

**Запасной вариант.** Свой распределённый БПФ: внутри слоя 2D-преобразование локально, потом пересылка и преобразование по третьей оси.

**Как выбрать.** Итерации ближе к куратору и дают больше работы; свой БПФ проще, но добавляет второй механизм обмена. Сравнение «один глобальный обмен против многих локальных» — готовый результат для отчёта, если хватит сил на оба.

### Развилка 5. Как резать куб — решено: слои

| Вариант | Соседей у узла | Плюсы | Минусы |
|---|---|---|---|
| **Слои по одной оси** | 2 | просто; три узла — три слоя | на десятках узлов масштабируется хуже |
| Карандаши (по двум осям) | 4 | лучше масштабируется | код обмена заметно сложнее |
| Кубики 2×2×2 | 6 | наименьшая поверхность обмена | нужно 8 узлов; плохо сочетается с БПФ |

Карандаши имеют смысл, только если дадут кластер на 16 и более узлов.

### Развилка 6. Где взять три машины — открыто

| Вариант | Плюсы | Минусы |
|---|---|---|
| Кластер НГУ | бесплатно, настоящий | неизвестно, когда дадут, что там стоит и есть ли GPU |
| Три своих машины в локальной сети | доступно сразу; задержки сети видны наглядно; сами настраиваем соединение | для больших сеток не годится |
| Облако: три CPU-инстанса | недорого, быстро | платно за каждый час |
| Облако: три GPU | быстро считает | дороже на порядок |
| Купить три видеокарты | своё | дороже всего |

**Рекомендация.** Письмо в НГУ отправить сразу; отлаживать тремя процессами на одной машине; первую демонстрацию делать на своих машинах, соединённых по сети; облако — запасной вариант для финального прогона. Для перехода на GPU выяснить, у кого в команде какие видеокарты и есть ли GPU на кластере.

**Что спросить у кластера:** сколько узлов и на сколько дают, версии MPI, есть ли GPU и CUDA, какие модули установлены (HDF5, FFTW), какая система очередей.

### Развилка 7. CPU или GPU — предварительно: старт на CPU, переход на GPU как можно раньше

CPU-версия нужна, чтобы отладить физику и обмен между машинами. Как только газ на одном узле проходит тесты, начинается перенос на GPU; откладывать его на второй семестр не планируем.

| Вариант | Плюсы | Минусы |
|---|---|---|
| CPU + MPI + OpenMP | проще отладка; работает на любых машинах | медленнее |
| GPU | на порядок быстрее; сеточные схемы ложатся хорошо | сложнее отладка; нужны машины с видеокартами |

**Порядок:**

1. Газ и гравитация на одном узле, CPU: физика проверена тестами.
2. Обмен между машинами на CPU: соединение и протокол отлажены.
3. Перенос циклов по ячейкам на GPU. Начинать можно параллельно с шагом 2, потому что он не трогает обмен.
4. Несколько машин, на каждой GPU: один MPI-процесс на одну видеокарту, как в Cholla.

Код с самого начала пишется с расчётом на перенос: данные в плоских массивах, циклы по ячейкам без зависимостей между итерациями.

**Чем писать под GPU — открыто:**

| Вариант | Плюсы | Минусы |
|---|---|---|
| CUDA напрямую | полный контроль; много примеров; так написана Cholla | только NVIDIA; CPU-код и GPU-код живут раздельно |
| Kokkos | один и тот же код собирается и под CPU, и под GPU | сложнее сборка; свой стиль кода |
| OpenACC | директивы поверх обычных циклов, минимум переписывания | зависит от компилятора; меньше контроля |

Выбор зависит от того, какие видеокарты есть у команды и на кластере и есть ли у кого-то опыт CUDA.

**Что меняется при переходе:**

- **Обмен гало.** Граничные слои упаковываются на GPU, копируются в обычную память и уходят по MPI. Прямая пересылка из памяти GPU — позже, если обмен окажется узким местом.
- **Гравитация.** Итерационный решатель переносится на GPU так же, как газ; распределённый БПФ на нескольких GPU заметно тяжелее. Это довод в пользу итераций в развилке 4.
- **Память.** Сетку ограничивает память видеокарты: 512³ требует около 5 ГБ, 1024³ — около 43 ГБ на все карты вместе.
- **Рендер.** Остаётся на CPU: он оффлайновый, скорость не критична.

### Развилка 8. Начальные условия — предварительно: свой генератор

| Вариант | Плюсы | Минусы |
|---|---|---|
| Свой генератор | около сотни строк поверх БПФ; нет зависимости | надо проверять |

| Уровень | Что входит |
|---|---|
| Минимум | 1D-тесты, сохранение массы, три процесса против одного, видео рядом с эталоном |

### Развилка 10. Рендер — решено: свой на CPU

| Вариант | Плюсы | Минусы |
|---|---|---|
| **Свой проход лучей на CPU с OpenMP** | просто; полный контроль | медленно, но для оффлайна неважно |
| Свой на GPU | быстро | лишняя сложность в первом семестре |
| Готовый ParaView или yt | работает сразу | не своя работа; только для быстрого просмотра |
| Рендер внутри расчёта | не нужны терабайты снимков | камера задаётся заранее; см. раздел 15 |
| OpenGL в реальном времени | интерактивность | уже упёрлись в 10 кадров в секунду |

### Развилка 11. Формат данных — предварительно: HDF5

| Вариант | Плюсы | Минусы |
|---|---|---|
| HDF5, по файлу на процесс | стандарт; сжатие; атрибуты; читается из Python | зависимость |
| Параллельный HDF5, один файл | удобно | может не быть на кластере |
| Сырой бинарный файл плюс описание | никаких зависимостей | всё руками |

Сжатие снимков (логарифм плотности в 8 или 16 бит, позже ZFP или SZ) — второй семестр. Важно: сжатый формат годится для снимков и рендера, считать в нём нельзя.

### Развилка 12. Старый код — предварительно: писать заново

| Вариант | Плюсы | Минусы |
|---|---|---|
| Писать заново, перенести сплайн камеры | чистая архитектура | теряем наработки |
| Дорабатывать старый | привычный код | всё в `main.cpp`; физика другая; OpenGL не нужен |

Старый код полезен как точка сравнения: сколько тянул он и сколько тянет новый. Что именно он умеет — уточнить, в этот репозиторий он не залит.

### Алгоритмы гравитации

| Где | Алгоритм | Библиотека |
|---|---|---|
| Один узел | БПФ: прямое, деление на k², обратное | FFTW; на GPU — cuFFT |
| Несколько узлов, первый вариант | сопряжённые градиенты с тёплым стартом | свой код |
| Несколько узлов, целевой вариант | многосеточный метод: V-цикл, красно-чёрное сглаживание | свой код |
| Эталон для сверки | распределённый БПФ | FFTW-MPI |

### Начальные условия

| Задача | Алгоритм |
|---|---|
| Спектр мощности | формула Эйзенштейна–Ху |
| Случайное поле | гауссов шум в пространстве Фурье, умноженный на корень из спектра, обратное БПФ |
| Скорости | линейная теория, растущая мода |
| Случайные числа | `std::mt19937_64` с фиксированным зерном |

### Распределённая часть

| Задача | Решение |
|---|---|
| Разрезание куба | слои по одной оси |
| Границы между узлами | гало толщиной 1–2 ячейки |
| Периодичность | первый и последний узел — соседи |
| Перезапуск | контрольные точки раз в N шагов |
| Замеры | таймеры по фазам, сильное и слабое масштабирование |
| Профилирование | `perf` для одного узла; Score-P или mpiP для обмена |

### Данные

| Что | Чем |
|---|---|
| Снимки и контрольные точки | HDF5 с блоками и сжатием deflate |
| Сжатие для рендера | логарифм плотности в 8 или 16 бит |
| Сжатие с потерями, второй семестр | ZFP или SZ |
| Эталонные кубы | CAMELS Multifield Dataset, Quijote |

### Визуализация

| Задача | Алгоритм или средство |
|---|---|
| Объёмный рендер | пошаговый проход луча, свечение и поглощение |
| Значение между ячейками | трилинейная интерполяция |
| Цвет | передаточная функция от логарифма плотности |
| Камера | сплайн Катмулла–Рома |
| Плавность во времени | интерполяция между снимками |
| Ускорение | OpenMP по строкам кадра; ранний выход непрозрачного луча |
| Запись кадров | PNG через `stb_image_write` |
| Сборка видео | ffmpeg, H.264 или H.265 |
| Быстрый просмотр | ParaView или yt |

### Анализ

| Задача | Чем |
|---|---|
| Спектр мощности | БПФ плотности и усреднение по оболочкам; свой скрипт или Pylians |
| Точное решение блина Зельдовича | формула в Python |
| Линейный рост | численный интеграл фактора роста |
| Графики масштабирования | matplotlib |

### Чего сознательно не берём

- **FFTW-MPI как основной решатель** — скрывает распределёнку.
- **Готовые каркасы вроде AMReX** — делают разрезание и гало за нас.
- **Адаптивная сетка** — резко усложняет обмен; равномерной хватает.
- **OpenGL в реальном времени** — не тянет объём данных.
- **NCCL** — библиотека для нейросетей, не для обмена гало.

## 15. Своя исследовательская идея

Новый метод расчёта Вселенной за семестр не придумать. Реален небольшой собственный приём на стыке тем, который в таком виде никто не мерил.

| Идея | Суть | Новизна | Риск |
|---|---|---|---|
| Сжатый обмен гало | граничные слои пересылаются в 8 или 16 бит, счёт идёт в полной точности; меряем, сколько точности можно отдать и насколько быстрее обмен | поиск не нашёл такой работы для обмена гало | низкий: результат будет в любом случае |
| Параллельность по времени (Parareal) | приближение Зельдовича предсказывает состояние в нескольких моментах, точные расчёты между ними идут одновременно | такого сочетания поиск не нашёл | высокий: для задач с переносом вещества сходится плохо |
| Рендер внутри расчёта | каждый узел пускает лучи через свой кусок во время симуляции, кадр склеивается | низкая: так делают большие проекты | средний: ракурс нельзя поменять после расчёта |
| Редкий обмен для гравитации | гало потенциала пересылается не на каждой итерации | средняя | низкий: надстройка над своим решателем |

**Рекомендация.** Сжатый обмен гало как основная своя идея: дёшево, гарантированный результат, соединяет две темы куратора — сжатие и задержки сети. Параллельность по времени — смелая заявка на второй семестр и прямой ответ на слова куратора «время нельзя сегментировать».

**Оговорка.** Новизна оценена по одному поиску. До того как писать «впервые», нужен день целевого поиска литературы. Безопасная формулировка — «исследуем, насколько…».

## 16. Этапы

Подробный план с задачами, вехами и датами — [plan.md](plan.md). Ниже — укрупнённо.

| Недели | Что готово |
|---|---|
| 1–2 | уравнения зафиксированы; 1D-прототип на Python с блином Зельдовича; скелет библиотеки; письмо про кластер; три машины соединены и запускают тестовую MPI-программу; рендер читает эталонный куб |
| 3–5 | 3D-газ с гравитацией на одном узле, 256³; начальные условия; первая паутина |
| 6–8 | три процесса: обмен гало, итерационный Пуассон, совпадение с одним процессом; параллельно — перенос циклов газа на GPU |
| 9–10 | три настоящие машины; замеры масштабирования и сети; прогон 512³; GPU на одном узле, затем на нескольких |
| 11–12 | видео, сравнение с эталоном, отчёт |

**Уровни готовности:**

| Уровень | Что входит |
|---|---|
| Минимум | газ на одном узле, 256³, 1D-тесты пройдены, видео из рендера |
| Цель | три машины, 512³–1024³, совпадение с одним процессом, масштабирование, разбивка времени шага; газ на GPU хотя бы на одном узле |
| Если останется время | три машины с GPU, второй порядок схемы, спектр мощности против эталона, сжатый обмен гало |

**Второй семестр:** сжатие снимков, адиабатический газ, сетки больше 1024³, многосеточный решатель, прямая пересылка из памяти GPU, частицы тёмной материи поверх газа, параллельность по времени.

## 17. Что на выходе

1. Библиотека и программа, запускаемая одной командой с конфигом.
2. Видео эволюции и пролёта через куб рядом с эталоном.
3. Графики тестов: блин Зельдовича, линейный рост.
4. Графики масштабирования и разбивка времени шага на счёт, гравитацию и обмен.
5. Сравнение со старым кодом: сколько тянул он и сколько новый.
6. Отчёт с уравнениями, схемой разрезания и протоколом обмена.

## 18. Риски

| Риск | Что делаем |
|---|---|
| Схема разваливается в плотных узлах | порог плотности, меньший шаг, сначала отладка в 1D |
| Слишком много шагов | начать с 256³, мерить с первого дня |
| Итерации Пуассона сходятся медленно | тёплый старт; запасной вариант — свой распределённый БПФ |
| Кластер НГУ не дадут вовремя | три своих машины в сети; облако на финальный прогон |
| Паутина не похожа на эталон | сначала количественные тесты в 1D, потом 3D |
| Газ даёт заметно другую структуру, чем тёмная материя | сравнивать с кубами плотности газа, а не только тёмной материи; запасной путь — PM |
| Разные версии библиотек на машинах | контейнер или скрипт установки с фиксированными версиями |
| Машины разной мощности, медленная тормозит всех | слои разной толщины, пропорционально скорости машины |
| Сеть оказывается узким местом | провод вместо Wi-Fi; замер задержки и пропускной способности до начала прогонов |
| Переход на GPU затягивается | CPU-версия остаётся рабочей; GPU-результат сверяется с ней по модулям |

## 20. Что поправили в исходном описании

| Было | Как на самом деле |
|---|---|
| «Газ без давления», перетекание только плотности | без давления схема не переживает пересечение потоков; берём газ с давлением |
| Пуассон как часть «шаблона 3×3×3» | потенциал зависит от всего куба; нужен либо БПФ, либо много итераций |
| Обмен по «MPI / NCCL» | NCCL — для обучения нейросетей; нужен только MPI |
| FFTW-MPI разбивает куб и решает Пуассона | это готовое распределённое решение, куратор против |
| «512³–1024³ в double — память кончится мгновенно» | 512³ в double — 1 ГБ на поле, 1024³ — 8,6 ГБ; распределёнка нужна с 1024³ и выше |
| Квантование в uint8 в задачах первой недели | это формат снимков, не расчёта; куратор относит сжатие ко второму семестру |
| Сравнение «геометрии» с Millennium | сравниваем воксельные кубы с CAMELS и Quijote плюс количественные тесты в 1D |
| Масштабирование на трёх узлах | три точки мало; меряем по числу процессов |
| Начальные условия и проверка не назначены никому | добавлены в зону первого человека |
| 4K-видео | честно для сеток от 1024³; для 512³ — Full HD |
