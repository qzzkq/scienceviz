# Распределённая сетка и прототип диффузии

Библиотека `svmpi` обменивает граничные слои между блоками
`svcore::Grid3D`. В примере `mpi_diffusion` этот обмен выполняется на каждом шаге.

## Локальная среда

Для воспроизводимого первого запуска на Linux x86_64:

```bash
python3 -m venv build-mpi-env
build-mpi-env/bin/python -m pip install mpich==5.0.2
export PATH="$PWD/build-mpi-env/bin:$PATH"
cmake -S . -B build-mpi -DSV_ENABLE_MPI=ON -DCMAKE_BUILD_TYPE=Debug \
  -DMPI_CXX_COMPILER="$PWD/build-mpi-env/bin/mpicxx" \
  -DMPIEXEC_EXECUTABLE="$PWD/build-mpi-env/bin/mpiexec"
cmake --build build-mpi --parallel 4
ctest --test-dir build-mpi --output-on-failure
python3 scripts/verify_mpi.py --build build-mpi \
  --mpiexec "$PWD/build-mpi-env/bin/mpiexec" --output-dir out/mpi-validation
```

Пакет MPICH публикуется проектом mpi4py; C++-код использует стандартный C API
MPI из `mpi.h`, библиотека Python mpi4py для него не нужна. Такой пакет подходит
для локальной проверки. На кластере нужно использовать MPI, рекомендованную
администраторами, и пересобрать проект в новом каталоге сборки.
[Описание бинарных пакетов MPI](https://mpi4py.readthedocs.io/en/stable/install.html).

Для уже установленной системной MPI достаточно `-DSV_ENABLE_MPI=ON`, если
`mpicxx` и `mpiexec` находятся в PATH. Не смешивайте компилятор-обёртку и launcher
от разных реализаций MPI.

## Контракт обмена

- `split_z(Nz, ranks, rank, halo)` возвращает локальный размер и глобальное
  смещение. Для 256/3 это 86/85/85, смещения 0/86/171.
- Каждый блок содержит минимум `halo` собственных z-плоскостей.
- `HaloExchange` принимает ссылку на сетку и набор обмениваемых полей.
  Локальные размеры z могут различаться; x/y, толщина гало и набор полей одинаковы.
- Создание и уничтожение обменника коллективные. Объект уничтожается до
  `MPI_Finalize`; сетка живёт дольше объекта и сохраняет размеры.
- Сначала заполняется периодическое гало x/y на собственных z-плоскостях,
  затем два `MPI_Sendrecv` передают z-полосы вместе с краями x/y.
- Коммуникатор дублируется, поэтому теги обмена не конфликтуют с тегами других
  модулей. Для одного ранга корректно работает обмен с самим собой.
- `global_time_step` проверяет все локальные dt и возвращает общий минимум
  через `MPI_Allreduce`. Недопустимый dt на одном ранге отвергается всеми.

Обмен проверен на 1/2/3 рангах для всех пяти текущих полей, гало 1/2,
неравномерного разбиения, тонких блоков и повторных обменов. Проверяются
собственные ячейки, грани, рёбра и углы. Тесты также проверяют выбор поля,
несогласованные списки полей и недопустимые dt.

Это готовый интерфейс обмена и общего шага для сеточного ядра. Вызовы в этапах
реального газового решателя требуют отдельной интеграции, когда C++-решатель
будет доступен. Полный газовый шаг этим прототипом не реализован.

## Пример расчёта

```bash
build-mpi-env/bin/mpiexec -n 3 build-mpi/mpi_diffusion \
  --nx 17 --ny 13 --nz 19 --halo 2 --steps 20 --output out/diffusion.f32
```

Предварительно создайте каталог `out`. Задача: `du/dt = Laplacian(u)` на
периодическом единичном кубе. Коэффициент диффузии равен 1, начальное поле —
положительная константа плюс три синусоидальные моды. Пространственная схема
центральная, время — явный Euler. Используется
`dt = 0.45 / (Nx² + Ny² + Nz²)` при пределе устойчивости
`1 / (2 * (Nx² + Ny² + Nz²))`.

После шага поле собирается на rank 0 только для проверки. Выполняются:

1. Сравнение с независимым последовательным расчётом без Grid3D и MPI.
2. Проверка известного затухания мод дискретной схемы.
3. Проверка конечности значений и сохранения суммы.
4. Скриптом `verify_mpi.py` — сравнение полных полей от отдельных запусков
   на 1, 2 и 3 рангах, запись контрольных сумм и максимальной ошибки.

Допуски float32: `1e-6` для совпадения полей и относительного изменения суммы,
`5e-6` для мод. Программа возвращает ненулевой код при провале проверки.
Для совпадающего окружения дополнительно фиксируется побитовое совпадение;
оно не обещается между разными компиляторами и архитектурами.

Прототип ограничен размерами до 128 по оси: в нём специально оставлена полная
последовательная проверка. Дамп — только float32 в машинном порядке байтов,
x быстрый, без заголовка. Это проверочный формат, он не является форматом
снимков основного рендера или контрольных точек.

## Времена

JSON в stdout содержит `compute_s_max`, `halo_s_max`, `loop_s_max` — максимум
накопленного времени фазы по всем рангам. Заполнение x/y включено в обмен,
копирование нового поля — в счёт. Сбор поля, запись и последовательная
проверка выполняются вне измеряемого цикла.

Максимумы разных фаз могут принадлежать разным рангам: их нельзя складывать
и выдавать за общее время. Для времени расчёта используется `loop_s_max`.
Малые локальные запуски проверяют правильность и работу таймеров; они не
подтверждают ускорение на нескольких физических машинах.

Для замера используйте отдельную Release-сборку, одинаковые параметры,
несколько повторов и сохранённые сырые JSON. Сравнивайте медиану и разброс,
а не лучший отдельный запуск.

```bash
cmake -S . -B build-mpi-release -DSV_ENABLE_MPI=ON -DCMAKE_BUILD_TYPE=Release \
  -DMPI_CXX_COMPILER="$PWD/build-mpi-env/bin/mpicxx" \
  -DMPIEXEC_EXECUTABLE="$PWD/build-mpi-env/bin/mpiexec"
cmake --build build-mpi-release --parallel 4
python3 scripts/benchmark_diffusion.py --build build-mpi-release \
  --mpiexec "$PWD/build-mpi-env/bin/mpiexec" --size 64 --steps 50 --repeats 5
```

Бенчмарк сохраняет исходные замеры в `timings.csv` и таблицу для графиков
в `timings-phases.csv`. Каждому повтору соответствуют три строки в миллисекундах.
Фаза `total` берётся из измеренного `loop_s_max`. Для построения графика
установите Matplotlib и выполните из корня репозитория:

```bash
python3 prototype/plot_timings.py out/mpi-benchmark/timings-phases.csv --out out/mpi-benchmark/timings.png
```
